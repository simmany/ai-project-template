# ai-project-template

사람과 AI 에이전트가 같은 폴더에서 일할 때 요청, 자료, 기준, 기록, 결과물을 어디에 두고 어떤 규칙으로 다룰지 정해 둔 작업 폴더 템플릿입니다. 폴더 하나에 일하는 법(`AGENTS.md`)과 다섯 개의 자리가 들어 있어서, 에이전트에게 폴더를 열어 주면 같은 규칙으로 일하고 기록을 남깁니다. 개발자가 아니어도 쓸 수 있습니다. 이 템플릿은 2026 AI 미니컨퍼런스의 세션 '위임한 일을 해내는 코딩·업무 에이전트, 그 일을 챙기는 비서 에이전트'에서 소개합니다. 이 저장소에는 템플릿(현재 v1.4)과 함께, 같은 개념을 설명하는 교재 3편이 들어 있습니다.

## 시작하는 법

1. 내려받기: [릴리스 페이지](https://github.com/simmany/ai-project-template/releases/latest)에서 `ai-project-template_v1.4.zip`을 내려받아 압축을 풉니다.
2. 폴더 이름 바꾸기: `ai-project-template_v1.4` 폴더의 이름을 내 프로젝트 이름으로 바꿉니다.
3. 자료와 기준 넣기: 이 일의 배경이 되는 자료는 `input/`에, 매번 말하지 않아도 지켜야 할 기준은 `rules/`에 파일로 넣습니다.
4. 폴더 열어 주기: 쓰는 도구에서 이 폴더를 엽니다(아래 '도구별로 폴더를 여는 방법').
5. 첫 요청 보내기: 아래 문장을 에이전트에게 보냅니다. 맨 윗줄이 이 폴더의 약속이고, 둘째 줄은 예시 요청이니 내 일에 맞게 바꿉니다.

```
AGENTS.md를 먼저 읽고 시작해줘.
input/교육요청서.md를 바탕으로 신입 사원 AI 교육 제안서 초안을 만들어서 output/에 저장해줘.
```

일이 끝나면 대화창이 아니라 폴더를 확인합니다. `workflow/`에 요청과 결과 기록이, `output/`에 결과물이, `_workspace/memory/status.md`에 지금 상태가 남습니다.

대화를 닫고 새 대화에서 이어 갈 때는 폴더만 다시 연결하고 아래 문장을 보냅니다. 앞 대화를 알려 주지 않아도 폴더의 기록으로 어디까지 했는지 답하면 제대로 동작하는 것입니다.

```
AGENTS.md를 먼저 읽고, status.md를 바탕으로 지금 상태와 다음 할 일을 알려줘.
```

주의: 압축을 풀었을 때 `ai-project-template_v1.4` 폴더 안에 같은 이름의 폴더가 한 번 더 있으면(Windows의 '압축 풀기'에서 생길 수 있습니다) 안쪽 폴더를 프로젝트 폴더로 쓰세요. `AGENTS.md`가 바로 보이는 폴더를 에이전트에게 열어 줘야 합니다.

## 폴더 구성

이 저장소의 구성입니다. 가져가서 쓸 것은 `ai-project-template_v1.4/` 폴더 하나입니다.

```
ai-project-template/
├── README.md
├── LICENSE
├── docs/
│   ├── 01-chatbot-to-agent.html
│   ├── 02-coding-agent-to-work-agent.html
│   ├── 03-assistant-agent.html
│   ├── LICENSE.md
│   └── index.md
└── ai-project-template_v1.4/
    ├── AGENTS.md
    ├── CLAUDE.md
    ├── _workspace/
    │   ├── drafts/
    │   └── memory/
    │       └── status.md
    ├── input/
    │   └── README-TEMPLATE.md
    ├── output/
    ├── rules/
    └── workflow/
        └── REQ-TEMPLATE.md
```

템플릿 폴더 안에서 누가 무엇을 채우는지는 `AGENTS.md`에 정해져 있습니다.

- `AGENTS.md`: 에이전트가 먼저 읽는 일하는 법. 폴더 정의, 작업 순서, 요청 파일 규칙이 들어 있습니다.
- `CLAUDE.md`: Claude Code가 시작할 때 읽는 파일입니다. 첫 줄 `@AGENTS.md`로 `AGENTS.md`를 불러옵니다. 이 줄은 지우지 마세요.
- `rules/`: 사람이 씁니다. 항상 지켜야 할 원칙, 작성 기준, 제약사항.
- `input/`: 사람이 씁니다. 이 작업을 위해 제공하는 자료(업무 배경, 요구사항, 문서, 데이터). `README-TEMPLATE.md`는 자료 목록을 만들 때 복사해 쓰는 양식이며, 없어도 됩니다.
- `workflow/`: 요청(REQ)은 사람이(말로 요청하면 AI가 대신 기록합니다), 수행 결과(RES)는 AI가 씁니다. 파일 이름은 `YYYY-MM-DD_REQ-NNN 요청 요약.md` 형식입니다. `REQ-TEMPLATE.md`는 복사해 쓰는 양식입니다.
- `_workspace/memory/`: AI가 다시 보기 위한 기록입니다. `status.md`에 프로젝트의 최신 상태가 남습니다. 삭제하지 않습니다.
- `_workspace/drafts/`: AI의 중간 산출물. 요청(REQ)별 하위 폴더에 둡니다. 삭제하지 않으며, 정리는 사람이 합니다.
- `output/`: AI의 최종 결과물. 덮어쓰지 않고 `기획안_v01.md`, `기획안_v02.md`처럼 버전을 붙여 추가합니다.

`rules/`, `output/`, `_workspace/drafts/`에 있는 `.gitkeep`은 빈 폴더를 유지하기 위한 파일입니다. 그대로 두세요.

## 도구별로 폴더를 여는 방법

하나만 고르면 됩니다. 아래 예에서 프로젝트 폴더 이름은 `교육제안서`입니다.

- Claude 데스크톱 앱: 메시지 입력창에 Chat과 Cowork 선택지가 보이면 Cowork를 고릅니다. 보이지 않으면 둘이 합쳐진 새 화면이니 그대로 진행합니다. 작업할 폴더로 프로젝트 폴더를 연결합니다. 이 폴더를 쓰는 동안에는 데스크톱 앱을 열어 둡니다.
- Claude Code: 터미널에서 폴더로 이동해 `claude`를 실행합니다. Claude 데스크톱 앱의 Code 탭에서 이 폴더를 열어도 됩니다. Claude Code는 시작할 때 `CLAUDE.md`를 읽고, 그 안의 `@AGENTS.md`를 따라 `AGENTS.md`까지 읽습니다.
- Codex: 폴더에서 `codex`를 실행합니다. Codex는 `AGENTS.md`를 읽습니다.
- ChatGPT Work: 작업 폴더로 프로젝트 폴더를 연결하고, 위의 첫 요청을 그대로 보냅니다.

```
cd "/Users/내이름/Projects/교육제안서"
claude
```

위는 Claude Code의 예입니다. 경로는 내 폴더에 맞게 바꾸고, Codex는 마지막 줄을 `codex`로 바꿉니다. 화면의 이름은 버전에 따라 다를 수 있습니다.

### 하네스 같은 팀 구성 도구와 함께 쓸 때

에이전트 팀을 꾸려 달라고 요청할 때 아래 두 가지를 요청에 넣으세요. 도구가 만든 팀이 이 폴더의 규칙을 깨지 않게 하려는 것입니다.

- 중간 산출물은 `_workspace/drafts/` 아래 요청(REQ)별 폴더에만 두고, `_workspace/` 폴더와 그 안의 `memory/`는 옮기거나 지우지 말라고 적습니다.
- `CLAUDE.md`의 첫 줄 `@AGENTS.md`는 그대로 두고, 도구의 기록은 그 아래에 추가하라고 적습니다.

## 교재 3편

템플릿의 바탕이 되는 개념을 설명하는 교재입니다. 브라우저에서 바로 읽을 수 있습니다. 같은 파일이 저장소의 `docs/`에도 있습니다.

### 1편. 챗봇에서 에이전트까지, 같은 그림으로 보기

챗봇과 에이전트는 둘 다 대화창으로 만나지만, 맡기는 일의 범위와 준비할 맥락, 일이 처리되는 곳이 다릅니다. 이 편은 그 차이를 도식으로 구분합니다. 읽고 나면 지금 어떤 모드(대화, 작업 요청, 프로젝트)로 말하는지 구분하고, 챗봇에서 저장된 것과 이번 응답에 실제로 들어가는 것을 구분하며, AI가 쓸 자료와 도구가 돌아가는 곳을 확인할 수 있습니다.

[01-chatbot-to-agent.html](https://simmany.github.io/ai-project-template/01-chatbot-to-agent.html)

### 2편. 코딩 에이전트에서 업무 에이전트까지, 같은 그림으로 보기

바이브 코딩이라는 말 아래에서 AI에게 일을 맡기는 방법이 만들어진 과정을 따라갑니다. 업무 위임, 컨텍스트 엔지니어링, 하네스 엔지니어링이 어디에서 나왔고 코드를 쓰지 않는 사람에게 왜 필요한지를 다룹니다. 읽고 나면 맡기는 단위가 커져 온 흐름과, 그 방법이 코드 밖으로 나와 업무 에이전트가 된 과정을 설명할 수 있습니다.

[02-coding-agent-to-work-agent.html](https://simmany.github.io/ai-project-template/02-coding-agent-to-work-agent.html)

### 3편. 비서 에이전트, 같은 그림으로 보기

비서 에이전트는 내가 말을 걸지 않아도 먼저 움직입니다. 이 편은 비서 에이전트가 챗봇, 작업 에이전트와 어떻게 다른지를 1편과 같은 그림으로 구분합니다. 읽고 나면 세 층이 대화를 묶고 기억하는 방식의 차이, 비서 에이전트를 움직이는 세 가지 시작 조건, 어디에서 멈추고 나에게 묻는지를 알고, 프로젝트 폴더로 작업 에이전트와 비서 에이전트를 연결하는 방법을 이해합니다.

[03-assistant-agent.html](https://simmany.github.io/ai-project-template/03-assistant-agent.html)

## 버전 기록

- v1.0: 처음 만든 버전. `AGENTS.md`, `CLAUDE.md`와 `rules/`, `workflow/`, `input/`, `_workspace/`, `output/` 폴더로 구성했습니다.
- v1.1: 같은 작업에 이어지는 요청을 요청 파일 하나에 번호로 모아 적고, 파일 이름 형식을 `YYYY-MM-DD_REQ-NNN_제목.md`에서 `YYYY-MM-DD_REQ-NNN 요청 요약.md`로 바꾸며, 결과를 `## 요청N` 제목으로 적도록 했습니다.
- v1.2: `input/README.md`를 `README-TEMPLATE.md`로 바꾸고, 두 양식 파일에 양식(샘플)이며 실제 요청이나 자료가 아니라고 적었습니다. `input/`에 README.md가 없어도 에이전트가 동작합니다.
- v1.3: `README-TEMPLATE.md`의 표를 한 줄 목록으로 바꾸고, 두 양식 파일의 안내도 목록으로 바꿨습니다.
- v1.4: `AGENTS.md`의 세 가지를 고쳤습니다(다른 파일은 v1.3과 같습니다).
  - 번호가 같은 요청이 다른 날짜에 이미 있으면, 중간 산출물 폴더 이름에 날짜를 붙입니다(예: `drafts/2026-11-15_REQ-001/`). 번호가 겹치지 않으면 이전처럼 `drafts/REQ-001/`입니다. 서로 다른 작업의 초안이 한 폴더에 섞이는 일을 막기 위해서입니다.
  - 이번 작업으로 지정하지 않은 요청 가운데 결과(RES)가 비어 있는 것이 있으면, 에이전트는 그 요청을 수행하지 않고 `status.md`의 '다음 할 일'에 적어 둡니다. 적어 두는 것뿐이므로 사람이 그 요청을 지정해 맡기기 전에는 수행되지 않습니다.
  - 결과(RES)를 적을 때 요청마다 네 항목(수행 내용, 주요 판단, 결과물 위치, 남은 일)을 이 이름 그대로 적도록 했습니다.

## 알려진 한계

- 동작 확인은 터미널의 Claude Code로 했습니다. 비서 에이전트는 ChatGPT Dots에서 예약을 만들고 한 번 실행해 보는 데까지만 확인했습니다. Claude 데스크톱 앱(Cowork), Codex, ChatGPT Work, Hermes, OpenClaw에서의 동작은 확인하지 않았습니다.
- 결과가 비어 있는 다른 요청이 있으면, 상태만 묻는 질문에도 `status.md`의 '다음 할 일'에 한 줄이 적힐 수 있습니다. 의도한 동작입니다.
- 해당하는 요청이 없는데도 결과가 비어 있는 다른 요청이 없다는 줄이 `status.md`에 적힌 적이 한 번 있었습니다.
- 비서 에이전트가 적어 둔 요청은 '다음 할 일'에 오르지만, 사람이 그 요청을 지정하기 전에는 수행되지 않습니다. 자동으로 이어서 진행되기를 기대하면 어긋납니다.
- 에이전트가 웹 검색 같은 권한을 요청하면 승인해야 일이 끝까지 갑니다.
