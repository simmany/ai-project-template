# AGENTS.md

## 폴더 정의
- rules/ : 항상 지켜야 할 원칙, 작성 기준, 제약사항. 작업 요청과 충돌하면 충돌 내용을 알리고 적용할 기준을 확인한다.
- workflow/ : 작업 요청(REQ)과 수행 결과(RES)의 시간순 기록. 작업 하나를 REQ 파일 하나에 기록한다.
  이번 세션에서 지정한 REQ만 수행하고, 지난 기록은 이력으로만 참고한다.
- input/ : 사람이 이 작업을 위해 제공한 자료(업무 배경, 요구사항, 문서, 데이터).
  파일 목록과 README.md(있으면)로 내용을 파악한 뒤, 필요한 파일만 읽는다.
- _workspace/memory/ : AI가 다시 보기 위한 기록. 삭제하지 않는다.
  - status.md : 프로젝트의 최신 상태(진행 상황, 주요 결정과 이유, 다음 할 일).
    작업별 상세 기록은 workflow/에 남기고, status.md는 지난 내용을 계속 덧붙이지 말고 최신 상태로 간결하게 갱신한다.
- _workspace/drafts/ : 중간 산출물. REQ별 하위 폴더에 둔다(예: drafts/REQ-001/, 같은 번호의 REQ가 다른 날짜에 먼저 있으면 drafts/2026-11-15_REQ-001/). 삭제하지 않으며, 정리는 사람이 한다.
- output/ : 최종 결과물. 적절한 하위 폴더에 저장하고, 덮어쓰지 않고 버전을 붙여 추가한다.
  (예: 기획안_v01.md, 기획안_v02.md)
- REQ-TEMPLATE.md, README-TEMPLATE.md : 복사해서 쓰는 양식(샘플). 실제 요청이나 자료로 다루지 않는다.

## 작업 순서
1. 시작: rules/, _workspace/memory/status.md, 이번 REQ를 먼저 읽는다.
   - status.md가 없으면 이번 요청을 바탕으로 처음 작성한다.
   - 프롬프트로 요청받으면 수행하기 전에 REQ 파일에 먼저 기록한다.
   - 지정하지 않은 REQ 가운데 RES가 비어 있는 것이 있을 때만, 수행하지 않고 status.md의 다음 할 일에 적는다. 이번에 한 일이 없어도 바로 적고, 이미 적혀 있으면 다시 적지 않는다.
2. 수행: input/에서 필요한 자료만 골라 읽는다. 중간 산출물은 _workspace/drafts/의 해당 REQ 폴더에 둔다.
3. 종료: 요청을 마칠 때마다 결과를 output/에 저장하고, REQ 파일에 RES를 기록한 뒤 _workspace/memory/status.md를 갱신한다.

## REQ 파일 규칙
- 파일명: `YYYY-MM-DD_REQ-NNN 요청 요약.md` (예: 2026-11-12_REQ-001 교육 기획안 작성.md)
  번호는 이어서 붙이고, 요약은 REQ-NNN 뒤에 한 칸 띄우고 짧게 쓴다. 사람이 만든 파일의 이름은 바꾸지 않는다.
- 구성: `# Objective`(목표), `# Context`(참고자료), `# Instruction`(요청사항), `# RES`(수행 결과). 양식은 workflow/REQ-TEMPLATE.md.
- Instruction: 요청을 번호 목록으로 적는다. 프롬프트로 받은 요청은 AI가 사람이 쓴 것처럼 기록한다.
  - 같은 작업에 이어지는 요청은 새 파일을 만들지 않고, 그 REQ 파일의 Instruction에 다음 번호로 추가한다.
  - 목표가 다른 새 작업일 때만 새 REQ 파일을 만든다.
  - 사람이 하지 않은 요청이나 요청에 없는 내용은 지어내지 않고, 불분명하면 확인한 뒤 기록한다. 단순 질문은 기록하지 않는다.
- RES: 요청 번호와 같은 제목(`## 요청1`, `## 요청2`) 아래에 결과를 기록한다.
  - RES는 요청마다 네 항목을 이 이름 그대로 적고 생략하지 않는다: 수행 내용, 주요 판단, 결과물 위치, 남은 일

## 사람과 AI의 영역
- 사람: rules/, workflow/의 REQ, input/
- AI: workflow/의 RES, _workspace/, output/ (프롬프트로 받은 요청은 REQ도 AI가 기록하되, 이미 적힌 요청은 고치지 않는다)
- 멀티 에이전트 작업에서는 대표 에이전트(팀을 이끄는 오케스트레이터나 PM)가 REQ·RES 기록과 status.md 갱신을 맡는다.
  팀원들은 맡은 작업의 결과를 대표 에이전트에게 전달한다.

## 작업노트에 비서를 위해 남기는 것
- 작업을 마칠 때 status.md 맨 아래 한 줄을 최신으로 고친다.
  형식: 상태: 진행 중 | 검토 대기 | 막힘 | 완료 · 다음 확인: YYYY-MM-DD
- 사람의 결정이 필요한 일은 '다음 할 일'에 '사람 확인:'으로 시작해 적는다.

## 비서 에이전트가 이 폴더를 볼 때
1. _workspace/memory/status.md를 먼저 읽는다.
2. 상태가 '검토 대기'면 검토할 파일의 위치를 사람에게 알린다.
3. 보고는 세 줄로 한다: 끝난 것, 사람이 결정할 것, 막힌 것.
   status.md와 output/에 지난 24시간 동안 바뀐 파일이 없으면 보고하지 않는다.
   다만 상태가 '완료'가 아니고 '다음 확인' 날짜가 오늘이거나 지났으면 보고한다.
4. 이 폴더의 파일은 읽기만 한다. 만들거나 고치거나 지우지 않는다.
5. 결과물을 밖으로 보내기 전에 사람의 승인을 받는다.
