# 5단계. workflow 폴더에서 요청과 기록 보기

`workflow/`는 일이 흘러간 기록이 쌓이는 폴더입니다. 무엇을 시켰고 어떻게 됐는지가 파일로 남습니다. 보통 대화 하나에 파일 하나가 생기고, 그 안에 요청이 1번, 2번으로 쌓입니다.

## 지금까지의 기록 확인하기

`workflow/` 폴더를 열면 `2026-11-21_REQ-001 교육 제안서 초안.md` 같은 파일이 있습니다. 2단계부터 내가 대화창에 보낸 요청을 에이전트가 받아 적은 것입니다. 열어서 아래를 찾아봅니다.

- 첫 줄 `작성: 프롬프트 기록`: 내가 대화창에 보낸 말을 에이전트가 받아 적었다는 표시입니다.
- `# Instruction`: 내가 한 요청이 1번, 2번으로 적혀 있습니다.
- `# AI Response`: 요청 번호마다 `## 요청1`, `## 요청2`가 있고, 그 요청을 마치며 에이전트가 한 보고가 적혀 있습니다.

## 요청 문서를 직접 써서 맡기기

대화창에 말하는 대신 요청을 파일로 먼저 써서 건넬 수 있습니다. 요청이 길거나, 미리 다듬어 두고 싶을 때 씁니다.

1. 탐색기(Windows)나 Finder(Mac)에서 `workflow/REQ-TEMPLATE.md`를 복사해 이름을 `2026-11-22_REQ-002 교육 일정표.md`처럼 바꿉니다. 날짜는 오늘, 번호는 `workflow/`에 있는 가장 큰 번호의 다음입니다. 이름 끝의 `.md`는 그대로 둡니다. 화면에 `.md`가 보이지 않으면 적지 않습니다.
2. 그 파일을 메모장(Windows)이나 텍스트 편집기(Mac)로 열고, 안에 있던 글을 지운 뒤 아래 내용을 넣어 저장합니다.

```
# Objective
인재개발팀장이 교육 일정을 한눈에 보고 결정할 수 있게 한다.

# Context
- @input/교육요청서.md
- @output/ 의 가장 최신 제안서

# Instruction
1. 3일 교육 일정표를 한 장으로 만들어 @output/ 에 저장해줘.

# AI Response
(AI가 요청 번호별로 작성)
```

3. 대화창에 그 파일을 첨부하고 아래처럼 보냅니다. 파일을 대화창으로 끌어다 놓거나 첨부 버튼을 씁니다. 업무 에이전트에서 새 대화로 시작한다면 맨 앞에 'AGENTS.md를 먼저 읽고,'를 붙입니다.

```
첨부한 요청 문서를 수행해줘. workflow 폴더에 있는 파일이야.
```

파일을 첨부하지 않고 이름을 적어서 맡겨도 됩니다. 파일 이름은 1번에서 지은 이름으로 바꿉니다.

```
workflow/2026-11-22_REQ-002 교육 일정표.md 요청을 수행해줘.
```

내 일로 할 때는 세 칸에 내 목표, 읽을 자료, 만들 것을 적습니다. `@input/...`, `@output/...`은 그 폴더의 파일을 가리킨다는 표시입니다.

## 확인하기

- 내가 만든 요청 파일의 끝에 `# AI Response`와 `## 요청1`이 채워졌습니다. 내가 쓴 요청은 그대로입니다.
- `output/`에 일정표가 생겼습니다.

## 왜 Objective, Context, Instruction으로 나누어 쓰나요

사람에게 일을 맡길 때 하는 말을 세 칸으로 나눈 것입니다.

- Objective(목표): 왜 하는 일이고 무엇이 되면 끝인지 적습니다. 요청에 적지 않은 상황을 만났을 때 에이전트가 판단하는 기준이 됩니다.
- Context(참고자료): 무엇을 읽고 일할지 적습니다. 읽을 자료를 짚어 주면 에이전트가 지어내지 않고 그 자료에서 찾습니다.
- Instruction(요청사항): 만들어 달라는 것을 번호를 붙여 적습니다. 응답도 같은 번호로 붙기 때문에 나중에 요청과 결과를 짝지어 볼 수 있습니다.

목표 없이 요청만 적으면 에이전트는 시킨 것만 하고, 자료 없이 목표만 적으면 에이전트는 짐작으로 채웁니다. 셋을 함께 적어야 맡긴 대로 돌아옵니다.
