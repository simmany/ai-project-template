# 6단계. Context와 Memory 구분하기

이 폴더에서 에이전트가 읽는 것은 누가 정해서 준 것이냐에 따라 둘로 나뉩니다.

- Context: 사람이 AI에게 주는 모든 정보와 데이터입니다. AI가 읽습니다.
- Memory: AI가 작성한 작업 기록입니다. AI가 읽습니다.

| 구분 | 누가 정하나 | 폴더의 어디에 있나 |
| --- | --- | --- |
| Context | 사람 | `rules/`(규칙), `input/`(자료), `workflow/`의 요청, `AGENTS.md`, 대화창에 보낸 말 |
| Memory | AI | `_workspace/memory/status.md`(지금 상태), `workflow/`의 AI Response(요청마다의 기록), `_workspace/drafts/`(중간 산출물) |

- 파일로 옮겨 적은 것이 에이전트여도 내용을 내가 정해서 주었으면 Context입니다. 3단계의 요청서와 4단계의 규칙이 그렇습니다.
- `output/`은 둘과 다릅니다. AI가 쓰고 사람이 가져다 쓰는 결과물입니다.
- 5단계 요청 문서의 Context 칸은 그 요청에서 읽을 자료를 짚는 자리입니다. 여기서 말하는 Context는 더 넓어서, 사람이 주는 것 전체를 가리킵니다.

## 따라 하기

지금 대화를 닫고, 1단계에서 연 폴더(프로젝트)에서 새 대화를 시작합니다. 그리고 아래처럼 보냅니다.

업무 에이전트(ChatGPT Work, Claude)에서는 이렇게 보냅니다.

```
AGENTS.md를 먼저 읽고, status.md를 바탕으로 지금 상태와 다음 할 일을 알려줘.
```

코딩 에이전트(Codex, Claude Code)에서는 이렇게 보냅니다.

```
status.md를 바탕으로 지금 상태와 다음 할 일을 알려줘.
```

## 확인하기

앞 대화의 내용을 한 줄도 주지 않았는데 어디까지 했고 무엇이 남았는지 답하면 된 것입니다. 기억이 대화창이 아니라 폴더에 있다는 뜻입니다.

## 왜 구분하나요

- 결과가 마음에 들지 않을 때 고칠 곳이 달라집니다. 에이전트가 우리 사정을 몰랐다면 Context를 고칩니다(자료를 더 넣거나 규칙을 고칩니다). 앞에서 한 일을 잊었다면 Memory를 봅니다(`status.md`에 적혀 있는지 확인합니다).
- Context는 내가 책임지고 채우는 곳이고, Memory는 에이전트가 채우는 곳입니다. 그래서 `_workspace/memory/`의 파일은 지우지 않습니다.
- 챗봇의 메모리 기능은 서비스 안에 있어서 내가 열어 보거나 다른 AI에서 그대로 쓰기 어렵습니다. 이 폴더의 Memory는 파일이어서 내가 열어 볼 수 있고, 다른 에이전트도 그대로 읽습니다.
