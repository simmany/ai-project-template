# 6단계. 코딩 요청 해 보기

지금까지는 문서를 맡겼습니다. 에이전트는 작은 프로그램도 만듭니다. 값을 바꿔 가며 계산해 보는 화면이나, 파일을 읽어 표로 정리하는 스크립트 같은 것입니다. 코드를 몰라도 됩니다. 무엇이 필요한지 말하면 에이전트가 만들고, 할 수 있는 데까지 직접 실행해 확인한 뒤 알려 줍니다. 실행해 보지 못한 것이 있으면 그것도 알려 줍니다.

`rules/` 폴더에 미리 들어 있는 `coding.md`가 이때 쓰는 기준이고, 그 옆의 `coding/` 폴더에 예제가 있습니다. 내가 방법을 정해 주지 않아도 에이전트는 이 기준에 따라 가장 단순한 방법으로 만들고, 정해진 자리에 둡니다. 기준의 내용은 아래 '코딩 기본 기준: 취지와 방법'에 있습니다.

## 따라 하기

실습은 둘입니다. 하나는 내가 열어 쓰는 화면이고, 하나는 에이전트가 만들어 쓰는 스크립트입니다. 업무 에이전트에서 새 대화로 시작한다면 첫 요청의 맨 앞에 'AGENTS.md를 먼저 읽고,'를 붙입니다.

먼저 화면입니다. 교육 인원이나 단가가 바뀌면 총 교육비가 얼마가 되는지 바로 볼 수 있게 합니다.

```
교육 인원, 일수, 항목별 단가를 바꿔 가며 총 교육비를 바로 계산해 보는 화면을 만들어줘. 최신 제안서의 예산 항목을 기본값으로 넣고, 합계가 예산 한도를 넘으면 표시해줘.
```

- 어떤 기술로 만들지는 적지 않았습니다. 에이전트는 기준에 따라 가장 단순한 것부터 고릅니다. 이 요청이라면 HTML 파일 한 장입니다.
- 명령을 실행해도 되는지 물으면 허락합니다. 만든 것을 직접 실행해 확인하려는 것입니다. 프로그램을 새로 설치해도 되는지 물으면 무엇을 왜 설치하는지 읽어 보고 정합니다.

다음은 스크립트입니다. 글자 수는 에이전트가 눈으로 세면 틀리기 쉽습니다. 세는 프로그램(스크립트)을 만들게 하고, 그것으로 세게 합니다.

```
최신 제안서의 장별 글자 수를 세는 스크립트를 만들고, 그 스크립트로 세어서 결과를 output/에 표로 저장해줘. 제안서를 고칠 때마다 다시 쓸 거야.
```

만든 스크립트는 폴더에 남습니다. 다음에는 만들어 달라고 하지 않고, 쓰라고만 하면 됩니다.

```
만들어 둔 스크립트로 제안서 v02의 글자 수도 세어서 output/에 저장해줘.
```

## 확인하기

- 폴더에 `codebase/`가 생겼습니다. 그 안에 폴더가 둘 있고(이름은 에이전트가 짓습니다), 하나에는 `index.html`이, 하나에는 이름이 `.py`로 끝나는 스크립트가 있습니다. 폴더마다 무엇이고 어떻게 실행하는지 적은 `README.md`가 있습니다.
- `index.html`을 더블클릭하거나 브라우저 창에 끌어다 놓으면 화면이 열립니다. 인원이나 단가를 바꾸면 합계가 바로 바뀌고, 예산 한도를 넘기면 표시가 나옵니다.
- `output/`에 장별 글자 수 표가 생겼습니다. 두 번째로 시켰을 때는 표만 하나 더 생기고, 스크립트는 새로 만들지 않았습니다.
- `workflow/`의 업무요청서에 요청과 처리 결과가 적혔습니다. 처리 결과에서 무엇을 기준으로 만들었는지(예: "기본 기준 `rules/coding.md`로 진행")와 실행해서 확인한 것, 확인하지 못한 것을 찾아봅니다.

에이전트가 화면을 브라우저로 열어 보지는 못했다고 하면, 내가 열어 보고 이상한 점을 본 대로 말해 줍니다. 스크립트를 실행하지 못했다고 하면 [막혔을 때](troubleshooting.md)의 '코딩 요청'을 봅니다.

## 코딩 기본 기준: 취지와 방법

### 왜 만들었나
AI에게 "대시보드 만들어 줘"라고만 하면, 할 때마다 다른 기술과 다른 폴더 구조로 만들고, 필요 이상으로 복잡하게 만들기도 합니다.
그래서 **사용자가 따로 기준을 주지 않았을 때 AI가 따를 기본값**을 정해 두었습니다.
회사의 업무 매뉴얼과 같습니다. 상사가 따로 지시하면 지시대로 하고, 지시가 없으면 매뉴얼대로 합니다.

### 규칙 파일과 예제의 역할
| 문서 | 역할 | 언제 읽나 |
|---|---|---|
| `rules/coding.md` | 판단 기준: 어디에 둘지(앱 폴더 구조 포함), 무엇으로 만들지, 언제 물을지 | 코딩할 때마다 |
| `rules/coding/`의 예제 파일 | 실제로 돌아가는 예제 코드 | 필요한 예제만 골라서 |

### 다섯 가지 원칙
1. **내가 정한 방법이 먼저입니다.** 요청이나 스킬로 방법을 정하면 AI는 그대로 따릅니다. 단, 그 방법을 적용하라고 한 작업에만 따르고, 나머지는 기본값으로 합니다.
2. **가장 단순한 것부터 만듭니다.** 필요한 이유가 생길 때만 한 단계씩 올라갑니다.
   - HTML 한 장: 파일을 열어 보고, 거르고, 내려받기
   - Python 스크립트: 파일을 넣으면 파일이 나오는 작업
   - SQLite: 데이터를 쌓아 두고 다시 고쳐야 할 때
   - Flask 서버: 화면 버튼으로 Python을 실행하거나, 비밀 키를 숨기거나, 여러 사람이 같은 데이터를 함께 고칠 때
3. **두는 곳이 정해져 있습니다.** 계속 쓰고 고치는 코드는 `codebase/`, 결과물은 `output/`에 둡니다. 내가 넣은 원본 자료(`input/`)는 AI가 읽기만 합니다.
4. **묻는 때가 정해져 있습니다.** 기본값 안에서는 묻지 않고 바로 만듭니다. 새 프로그램을 설치하거나, 쓰던 방식을 바꾸거나, 외부에 공개할 때만 먼저 묻습니다.
5. **어떤 방법이든 꼭 지킬 것이 있습니다.**
   - 비밀 키는 `.env`에만 둡니다.
   - 서버는 내 컴퓨터 안에서만 엽니다.
   - 이상한 입력을 조용히 넘기지 않습니다. 결과가 0건이면 빈 결과를 새로 쓰고, 필수 항목이 없으면 오류를 알립니다.
   - 다 만들면 사용자처럼 직접 실행해서 확인합니다.

### 한 줄 요약
**기준이 없으면 가장 단순하게, 기준이 있으면 그 기준대로. 어느 쪽이든 안전하게 만들고 직접 돌려서 확인합니다.**

## 내 업무에 쓸 때

- 요청에는 만드는 방법이 아니라 필요한 것을 적습니다. "거래처별 매출을 표로 보고 싶어", "매주 받는 엑셀 파일을 같은 양식으로 정리해줘"처럼 적으면 됩니다.
- 방법을 정해 주고 싶으면 요청에 적습니다. 그 작업은 내가 적은 방법으로 하고, 나머지는 기본 기준으로 합니다. 새 프로그램을 설치해야 하는 방법이면 에이전트가 먼저 묻습니다.
- 기준을 바꾸고 싶으면 `rules/coding.md`를, 예제를 바꾸고 싶으면 `rules/coding/`의 파일을 고칩니다. `rules/`는 내가 정하는 곳입니다. 코딩을 맡기지 않는다면 `coding.md`와 `coding/` 폴더를 지워도 됩니다.
- 계속 쓰는 코드는 `codebase/`에 남고, `README.md`에 실행하는 방법이 적혀 있습니다. 그래서 다음 대화에서도 "만들어 둔 것을 써줘"라고 할 수 있습니다.
- API 키나 비밀번호 같은 비밀값은 대화창에 붙여 넣지 않습니다. 대화창에 보낸 말은 업무요청서에 기록되고, 그 AI 에이전트를 운영하는 회사의 서버에서도 처리됩니다. 비밀값이 필요한 작업이면 에이전트에게 값을 넣을 파일(`.env`)을 만들어 두게 하고, 값은 그 파일에 내가 직접 적습니다. 파일이 어디에 있고 어떻게 여는지는 에이전트에게 묻습니다.
