# 7단계. Context와 Memory 관리

이 글은 AI가 일할 때 **무엇을 보고 일하는지(Context)**, 그리고 **무엇을 남겨 다음에 이어 가는지(Memory)**를 설명합니다. 예시는 ai-project-template 폴더 구조로 듭니다. 글에서 "이 폴더"는 이 구조로 만든 프로젝트 폴더를 말합니다.

## 들어가기 전에: 이 글에서 예로 드는 폴더

| 이름 | 무엇인가 |
|---|---|
| AGENTS.md | 이 폴더에서 일하는 법을 적은 파일. 에이전트가 읽습니다 |
| CLAUDE.md | Claude Code에게 AGENTS.md를 읽으라고 안내하는 파일 |
| rules/ | 항상 지켜야 할 규칙. 사람이 정합니다 |
| input/ | 일에 필요한 참고 자료 파일. 사람이 넣어 둡니다 |
| workflow/ | 업무요청서(REQ) 파일이 쌓이는 곳 (구조는 2장에서 설명) |
| output/ | 결과물. AI가 만듭니다 |
| _workspace/ | AI의 작업실. 이름 앞의 밑줄(_)은 사람이 아니라 AI가 쓰는 공간이라는 표시입니다 |
| _workspace/memory/status.md | 프로젝트의 지금 상태 메모(진행 상황, 다음 할 일). AI가 갱신합니다 |
| _workspace/drafts/ | 작업실 안의 요청별 별도 공간. `drafts/REQ-002/`처럼 업무요청서 번호마다 폴더가 생기고, AI가 그 요청의 중간 산출물(초안, 조사 메모 등)을 기록·저장합니다 |

## 1. Context

> **Context: 언어모델(LLM)이 한 번 답할 때마다 입력으로 받는 정보 전체**
> 지난 대화, 규칙, 파일, 도구의 사용 결과가 매번 통째로 다시 들어간다. 여기 없으면 모른다.

※ **왜 "언어모델(LLM)"인가요**
ChatGPT·Claude 같은 **챗봇**이나 Codex·Claude Code 같은 **에이전트**는 언어모델 그 자체가 아닙니다. 언어모델을 감싸고, 언어모델에 Context를 모아 넣어 주는 프로그램입니다. 그래서 같은 언어모델이라도 어떤 앱으로 쓰느냐에 따라 Context에 들어가는 것이 달라집니다(아래 6. 비교 참고). Context는 앱이 아니라 언어모델을 기준으로 봐야 합니다.

**Context의 세 가지 성질**
1. **매번 통째로 다시 들어간다.** 언어모델은 지난 대화를 기억하지 않습니다. 답할 때마다 지금까지의 대화가 처음부터 다시 입력됩니다. 대화가 이어지는 것처럼 보이는 건 이전 대화가 Context에 함께 들어가기 때문입니다.
2. **여기 없으면 모른다.** 폴더에 있는 파일도, 어제 나눈 대화도 이번 Context에 들어 있지 않으면 AI에게는 없는 정보입니다. 새 대화의 AI는 처음 만나는 다른 부서 사람과 같습니다.
3. **한 번에 들어갈 수 있는 양이 정해져 있다.** 이 한도를 context window라고 합니다. 많이 넣을수록 중요한 것을 놓치기 쉽고, 한도를 넘으면 오래된 내용부터 잘리거나 요약됩니다.

**비유:** 모든 자료는 서랍에 들어 있습니다. 언어모델(LLM)은 서랍에서 꺼내 책상 위에 올려놓은 것만 볼 수 있고, 답할 때마다 책상 위를 처음부터 다시 읽습니다.

## 2. Context에 들어가는 것

**범용 챗봇**
시스템 프롬프트, 맞춤형 지침, 메모리, 대화 기록(이 대화창에서 지금까지 주고받은 질문과 답), 사용자 프롬프트

(※ 다른 대화창의 내용은 여기에 들어가지 않습니다. 앱이 과거 대화를 참고하는 기능은 메모리에 해당합니다.)

**에이전트: 범용 챗봇의 다섯 가지에 세 가지가 더해집니다**

| # | 항목 | 쉽게 말하면 | 예 |
|---|---|---|---|
| 1 | 시스템 프롬프트 | AI 회사가 정한 기본 행동 수칙: 모든 사용자에게 똑같이 적용 | Claude Code, Codex가 기본으로 넣는 규칙 |
| 2 | 맞춤형 지침 → 프로젝트 지침 | 이 팀의 업무 매뉴얼: 이 폴더에서 일하는 법과 지켜야 할 규칙 | AGENTS.md, CLAUDE.md, rules/, 앱의 프로젝트 지침 입력란 |
| 3 | 메모리 | 인수인계용 작업 기록: 지난번에 남겨 둔 것 중 이번에 읽어 들인 내용 | 앱 메모리(나에 대한 정보, 원하는 답변 방식), status.md(진행 상황, 정한 것, 다음 할 일) |
| 4 | 대화 기록 | 이 대화창에서 주고받은 말과 한 일 | 지금까지의 요청, 답, 작업 과정 |
| 5 | 사용자 프롬프트 | 지금 받은 업무 지시 | "REQ-002 수행해줘" |
| +6 | 도구(tool) 목록 | AI의 손발: 무엇을 할 수 있고, 어떻게 쓰는지 | 파일 읽기·쓰기, 명령 실행, 웹 검색 |
| +7 | 스킬 목록 | 도서관의 장서 목록: 모든 책의 제목과 소개는 항상 들어가고, 책 본문은 필요한 것만 꺼내서 넣음 | 보고서 작성, 엑셀 정리, PPT 만들기 스킬 |
| +8 | 도구의 사용 결과 | 손발을 써서 얻은 결과 | 읽은 파일 내용, 실행 결과, 에러 메시지 |

※ **도구(tool) 목록이란**
언어모델은 글만 쓸 수 있습니다. 도구는 AI가 파일을 읽고 쓰고, 명령을 실행할 수 있도록 손과 발이 되어 줍니다. Context에 들어가는 도구 목록은 손발 그 자체가 아니라 "어떤 손발이 있고 어떻게 쓰는지"에 대한 설명입니다. 실제로 손발을 쓰고 나면 그 결과가 +8 도구의 사용 결과로 들어갑니다.

※ **업무요청서(REQ)란**
workflow/에 `2026-11-22_REQ-002 보고서.md`처럼 번호를 붙여 쌓이는 파일입니다. 네 칸으로 되어 있습니다.

```
# 목표 (Objective)
# 참고 자료 (Context)
# 요청 사항 (Instruction)
# 처리 결과 (Process & Result)
```

- **일을 맡기는 방법은 두 가지입니다.**
  - **직접 써서 맡기기:** 위의 세 칸(목표, 참고 자료, 요청 사항)을 채워서 맡깁니다.
  - **대화창에서 바로 시키기:** 평소처럼 대화창에서 그때그때 일을 시켜도 됩니다. AI가 대신 이 양식에 맞춰 받아 적습니다. AGENTS.md에 그렇게 하라고 정해 두었기 때문입니다. 단순한 질문이나 대화는 적지 않고, 업무와 관련해 일을 해 달라는 요청만 골라서 적습니다.
- **처리 결과**는 AI가 요청 사항마다 돌려주는 보고입니다. 요청 사항 1번에는 처리 결과 1번이 짝지어 붙습니다. AI는 무엇을 했고 결과물이 어디 있는지 적습니다. 일을 끝내지 못했다면 어디까지 했고 왜 멈췄는지 적습니다.

**요청 하나에 Context가 쌓이는 모습**

요청: "REQ-002 수행해줘" (workflow/에 있는 2번 업무요청서대로 일해 달라는 지시)
1. 시작할 때 시스템 프롬프트, AGENTS.md(일하는 법), 요청, 도구·스킬 목록이 들어갑니다.
2. rules/(지켜야 할 규칙)와 status.md(지금 상태 메모)를 읽으면 규칙과 메모리가 더해집니다.
3. REQ-002 파일을 읽으면 업무요청서 내용이 더해집니다.
4. input/의 참고 자료를 읽으면 자료가 더해집니다.
5. 보고서 파일을 저장하면 "저장했다"는 확인 메시지가 도구의 사용 결과로 더해집니다. 저장에 실패했다면 에러 메시지가 더해집니다. AI는 이 결과를 보고서야 저장이 됐는지 압니다. 그 뒤에 다음 일로 넘어가는데, 업무요청서 끝의 처리 결과(Process & Result) 칸에 무엇을 했고 결과물이 어디 있는지를 적는 일입니다.

읽을 때만이 아니라 저장하고 실행할 때도 그 결과가 Context에 쌓입니다. **AI는 자기가 한 일조차 Context에 들어온 결과를 보고 압니다.** 사람이 한 말은 한 줄인데, Context는 AI가 일하는 동안 계속 불어납니다.

## 3. Context Engineering

> **Context Engineering: 전체 자료 중에서 이번에 필요한 것을 골라 Context에 넣는 일**

- 필요한 것을 빠뜨리면 AI는 짐작으로 채웁니다.
- 너무 많이 넣으면 중요한 것을 놓칩니다.
- 원칙: 필요한 것은 빠짐없이, 필요 없는 것은 넣지 않는다.

이 폴더에서 고르는 주체는 셋입니다.
- **사람이 고른다:** 업무요청서의 참고 자료(Context) 칸에 읽을 파일을 적거나(`@input/회의록.md`처럼 파일을 가리킴), 파일을 첨부합니다.
- **규칙이 고른다:** AGENTS.md에 "일을 시작할 때 rules/, status.md, 이번 업무요청서를 먼저 읽는다"고 정해 둡니다.
- **AI가 고른다:** AGENTS.md의 규칙에 따라 input/ 폴더는 파일 목록과 안내 파일(README)만 먼저 보고, 필요한 파일만 읽습니다. 번호가 더 큰 업무요청서는 사람이 아직 쓰고 있을 수 있어서 열어 보지 않습니다.

업무요청서의 참고 자료 칸에 Context라는 영문이 붙은 건 우연이 아닙니다. 서랍에서 무엇을 꺼낼지 사람이 직접 짚어 주는 칸이기 때문입니다.

스킬도 Context Engineering의 한 방식입니다. 목록은 항상 넣어 두고, 본문은 필요할 때만 꺼내 넣어서 Context를 아낍니다.

## 4. Memory

> **Memory: AI가 다음에 이어서 일할 수 있도록 남긴 작업 기록**

- 이 폴더에서는 status.md(지금 상태 메모), 업무요청서 끝의 처리 결과(요청마다 남긴 보고), _workspace/drafts/(요청별 중간 산출물)가 Memory입니다.
- Memory도 서랍 속 자료입니다. 다음 작업에서 꺼내 책상 위(Context)에 올려야 쓰입니다.
- 새 대화에는 앞 대화가 Context에 없습니다. 그래도 status.md를 읽어 Context에 넣으면 이어서 일할 수 있습니다.

## 5. 이 폴더에서 보면

| 구분 | 누가 쓰나 | 폴더 |
|---|---|---|
| 사람이 준 자료 | 사람 | AGENTS.md, rules/, input/, 업무요청서의 목표·참고 자료·요청 사항 칸 |
| AI의 작업 기록 (Memory) | AI | status.md, 업무요청서의 처리 결과 칸, drafts/ |
| 결과물 | AI가 만들고 사람이 가져다 씀 | output/ |

이 자료들은 모두 서랍(폴더)에 있습니다. **Context는 그중 이번 일을 위해 꺼내서 책상 위에 올린 것입니다.**

## 6. 범용 챗봇 · 맞춤형 챗봇 · 에이전트 비교

| | 범용 챗봇 | 맞춤형 챗봇 (프로젝트) | 업무·코딩 에이전트 |
|---|---|---|---|
| 예 | ChatGPT, Claude, Gemini 기본 대화 | ChatGPT 프로젝트·GPTs, Claude 프로젝트, Gemini Gem | ChatGPT Work, Claude Cowork / Codex, Claude Code |
| 일하는 곳 | 대화창 | 프로젝트 안의 대화창 | 폴더 (대화창은 지시하는 창구) |
| 지침 | 계정 단위 맞춤형 지침 | 프로젝트 단위 지침 | 폴더 단위 지침 파일 (AGENTS.md) |
| 자료 | 그때그때 첨부 | 프로젝트에 올려 둔 지식 파일 | 폴더의 파일 (input/ 등) |
| 자료가 Context에 들어가는 방식 | 첨부하면 들어감 | 적으면 통째로 들어가고, 많으면 질문과 관련된 부분만 찾아서 넣음 | AI가 필요한 파일을 골라 읽음 |
| 메모리 | AI 회사 서버에 저장 (계정 단위), 설정 화면에서 확인 | AI 회사 서버에 저장 (프로젝트별로 나뉘기도 함), 설정 화면에서 확인 | 도구 기본: 내 컴퓨터의 숨김 폴더 / 이 폴더: 프로젝트 폴더의 파일 |
| Context를 채우는 주체 | 사람 | 사람과 앱 | AI |
| 결과가 남는 곳 | 대화창 | 대화창 (프로젝트 자료는 사람이 직접 올림) | 폴더에 직접 저장 |
| 가득 차면 | 오래된 대화부터 요약되거나 잘림 | 같음 | 훨씬 자주 생김 → 중요한 건 파일로 남김 |

**범용 챗봇 → 맞춤형 챗봇 → 업무·코딩 에이전트로 가면서 달라지는 것**
> **지침과 자료의 단위:** 계정 → 프로젝트 → 폴더
> **Context를 채우는 주체:** 사람 → 사람과 앱 → AI
> **결과:** 대화창의 답 → 대화창의 답 → 폴더의 파일

**업무 에이전트와 코딩 에이전트의 차이**
- 코딩 에이전트(Codex, Claude Code)는 시작할 때 지침 파일을 자동으로 Context에 넣습니다. Codex는 AGENTS.md를, Claude Code는 CLAUDE.md를 넣습니다. 이 폴더의 CLAUDE.md는 AGENTS.md를 읽으라고 안내하므로, 둘 다 결국 같은 규칙을 따릅니다.
- 업무 에이전트(ChatGPT Work, Claude Cowork)는 앱과 설정에 따라 스스로 읽지 않을 수 있습니다. 그래서 첫 요청에 "AGENTS.md를 먼저 읽고"라고 붙여 확실히 넣습니다.

**맞춤형 챗봇과의 연결**
- 맞춤형 챗봇에서 쓰던 방식을 더 구조화하고 확장한 것이 이 폴더 구조(ai-project-template)입니다. 프로젝트 지침은 AGENTS.md와 rules/로, 지식 파일은 input/으로 나뉘었고, 여기에 AI가 직접 쓰는 공간(workflow/, output/, _workspace/)이 더해졌습니다.
- 맞춤형 챗봇은 결과와 기록을 스스로 파일로 남기지 못합니다. 그래서 작업 기록(Memory)이 쌓이지 않습니다.
- 자료가 많을 때 질문과 관련된 부분만 찾아 넣는 것은 앱이 대신 해 주는 Context Engineering입니다.

## 7. 메모리는 어디에 저장되나

| | 저장 위치 | 확인 방법 | 다른 AI에서 |
|---|---|---|---|
| 범용 챗봇 · 맞춤형 챗봇 | AI 회사 서버 | 앱 설정 화면 | 그대로 쓰기 어려움 |
| 코딩 에이전트의 기본 메모리 | 내 컴퓨터 홈 폴더 안의 숨김 폴더 (.claude, .codex) | 숨김 폴더를 찾아서 열어야 함 | 그 도구만 읽음 |
| 이 폴더의 Memory | 내 프로젝트 폴더 (_workspace/, workflow/) | 파일을 그냥 열면 됨 (메모장으로 읽히는 마크다운 .md 파일) | AGENTS.md를 읽는 에이전트라면 모두 읽음 |

(※ 숨김 폴더: 이름이 점(.)으로 시작해서 Finder에서 기본으로는 보이지 않는 폴더입니다.)

**코딩 에이전트 기본 메모리의 세 가지 문제**
1. **찾기 어렵다.** Claude Code의 자동 메모리는 프로젝트 안의 `.claude/`가 아니라 홈 폴더 아래 `~/.claude/projects/-Users-...-my-project/memory/`에 저장됩니다. 프로젝트별 메모리인데 프로젝트 폴더 밖에 있습니다.
2. **읽기 어렵다.** 대화 기록은 Claude Code가 `~/.claude/projects/`에, Codex가 `~/.codex/sessions/`에 JSONL 형식으로 저장합니다. JSONL은 컴퓨터가 처리하기 좋게 한 줄에 기록을 하나씩 적는 형식이라, 사람이 읽기에는 불편합니다.
3. **그 도구 전용이다.** Claude Code의 메모리는 Codex가 읽지 않고, Codex의 기록도 Claude Code가 읽지 않습니다.

> 도구가 알아서 남기는 메모리는 그 도구를 위한 기록이고, 폴더의 Memory는 나와 모든 AI를 위한 기록이다.

이 폴더는 기록을 **보이는 곳에, 사람이 읽을 수 있는 형식으로, 특정 도구에 묶이지 않게** 남깁니다.

## 8. Context와 Memory를 왜 구분하나요

결과가 마음에 들지 않을 때 고칠 곳이 달라집니다.
- **우리 사정을 모르고 답했다면** 필요한 자료가 Context에 들어가지 않은 것입니다. 자료를 더 넣거나, 규칙을 고치거나, 업무요청서의 참고 자료(Context) 칸에 읽을 파일을 짚어 줍니다.
- **앞에서 한 일을 잊었다면** Memory를 확인합니다. status.md와 업무요청서의 처리 결과(Process & Result) 칸에 기록이 남아 있는지, 그리고 그것을 읽게 했는지 봅니다.

## 한눈에 정리 (세 문장으로 요약)

> **Context:** 언어모델이 한 번 답할 때마다 입력으로 받는 정보 전체. 여기 없으면 AI는 모른다.
> **Context Engineering:** 전체 자료 중에서 이번에 필요한 것을 골라 Context에 넣는 일.
> **Memory:** AI가 다음에 이어서 일하려고 남긴 작업 기록. Context에 들어가야 쓰인다.

## 따라 하기

Memory가 대화창이 아니라 폴더에 있다는 것을 확인해 봅니다. 지금 대화를 닫고, 1단계에서 연 폴더(프로젝트)에서 새 대화를 시작합니다. 그리고 아래처럼 보냅니다.

업무 에이전트(ChatGPT Work, Claude Cowork)에서는 이렇게 보냅니다.

```
AGENTS.md를 먼저 읽고, status.md를 바탕으로 지금 상태와 다음 할 일을 알려줘.
```

코딩 에이전트(Codex, Claude Code)에서는 이렇게 보냅니다.

```
status.md를 바탕으로 지금 상태와 다음 할 일을 알려줘.
```

## 확인하기

앞 대화의 내용을 한 줄도 주지 않았는데 어디까지 했고 무엇이 남았는지 답하면 된 것입니다. 기억이 대화창이 아니라 폴더에 있다는 뜻입니다. 그래서 `_workspace/memory/`의 파일은 지우지 않습니다.
