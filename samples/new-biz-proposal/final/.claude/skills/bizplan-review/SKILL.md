# 사업계획서 검토 — 평가위원 심사 + 팩트체크

검토의 목적은 점수를 매기는 것이 아니라 **집필가가 바로 고칠 수 있는 이슈 목록**을 만드는 것이다. 이슈마다 위치·근거·수정 방법이 있어야 수정 라운드가 1~2회 안에 끝난다.

두 역할은 같은 이슈 형식을 쓰고 영역을 나눈다.

| 역할 | 영역 | 이슈 ID |
|------|------|---------|
| 평가위원(bizplan-evaluator) | 구조·설득력·문체·쪽수·그림 배치·규정 | `E-01`… |
| 팩트체커(fact-checker) | 수치·출처·계산·일관성·날조 위험 | `F-01`… |

## 1. 공통 이슈 형식

```markdown
| ID | 심각도 | 위치 | 원문 인용 | 문제 | 수정 방법 |
|----|--------|------|----------|------|----------|
| E-03 | Major | 2.2.1 | "SOM 120억 원" | Bottom-up 산정식 없음 | 타깃 인구×도달률×전환율×객단가 식과 계수별 근거 추가 |
```

| 심각도 | 기준 | 예 |
|--------|------|----|
| Critical | 그대로 제출하면 탈락·신뢰 상실로 이어짐 | 지어낸 시험 결과·인터뷰·계약, 블라인드 위반, 목차 소목차 누락, 사업비 규정 위반, 장 사이 핵심 수치 모순 |
| Major | 해당 소목차 점수를 크게 깎음 | 출처 없는 핵심 수치, 산정 논리 없는 `[가정]`, 헤드라인 없음, 쪽수 20% 이상 초과, 경쟁사 비방 |
| Minor | 다듬으면 좋아짐 | 문장 길이, 표현, 그림 위치 조정, 사소한 표기 불일치 |

## 2. 평가위원 심사 절차

1. `custom-instruction/사업계획서 목차.txt`와 본문의 제목을 한 줄씩 대조한다. 누락·번호 오류·제목 변경은 Critical이다.
2. `custom-instruction/작가 페르소나.txt` 5절(대목차별 집필 포인트)과 `.claude/skills/bizplan-writing/references/section-guide.md`의 "평가위원의 질문·필수 요소·감점 요인"으로 소목차를 하나씩 채점한다.

| 점수 | 의미 |
|------|------|
| 5 | 질문에 바로 답하고 수치·출처로 뒷받침됨 |
| 4 | 답하지만 근거 하나가 약함 |
| 3 | 방향은 맞지만 근거가 대부분 가정·확인 필요 |
| 2 | 질문에 부분적으로만 답함 |
| 1 | 답하지 않음 |

`[창업자 입력 필요]`로 비워 둔 칸은 감점 사유가 아니다. 대신 작성 틀(무엇을 어떤 형식으로 채울지)이 있는지 본다. 틀이 없으면 Minor.

3. 문체: 소목차 첫 줄 헤드라인, 근거 3개 이내, 명사형 종결, 문장 50자 안팎, 형용사 대신 수치. 위반이 반복되면 대표 사례 3개와 함께 한 이슈로 묶는다.
4. 쪽수: 대목차별 본문 줄 수를 센다(`grep`/`awk`로 빈 줄·메모 블록(`>`)·자리 표시를 뺀 줄 수). 그림 1개 ≈ 1/3쪽, A4 1쪽 ≈ 25~30줄로 환산해 목차 배분과 비교한다.
5. 그림: 그림 계획과 `{{FIG:…}}` 위치를 보고, 주장 바로 뒤에 있는지, 같은 내용을 두 번 보여 주지 않는지, 빠진 핵심 그림(예: 공급망, 간트)이 없는지 본다.
6. 규정: 대표자·팀원 성명, 출신 학교, 식별 가능한 이력, 경쟁사 비방, 근거 없는 "최초·유일·독보적".
7. 3대 질문 점검: 대목차마다 Evidence(근거) / Why us(왜 이 팀) / So what(얼마를, 언제)이 드러나는지 한 줄 평을 쓴다.

## 3. 팩트체크 절차

1. **대조표 만들기:** 본문에서 숫자, 연도, 비율, 금액, 기관명, 비교 주장("~보다 N% 높음")을 모두 뽑는다. `grep -nE '[0-9]'`로 후보 줄을 찾은 뒤 하나씩 읽는다.
2. **판정:** 각 항목을 수치 시트(`02_writer_numbers*.md`) → 팩트 시트(`01_*_facts*.md`) → 데이터 인사이트 순으로 대조한다.

| 판정 | 의미 | 이슈 여부 |
|------|------|----------|
| 확인 | 수치 시트와 원천 자료가 일치하고 본문에 출처가 있음 | 아님 |
| 태그 적정 | `[가정]`(논리 있음)·`[확인 필요]`·`[창업자 입력 필요]`가 알맞게 붙음 | 아님 |
| 불일치 | 원천과 값·단위·연도·지역이 다름 | Major (핵심 수치면 Critical) |
| 출처 없음 | 수치 시트에도 팩트에도 없음, 태그도 없음 | Major |
| 논리 부족 | `[가정]`에 산정 논리가 없거나 틀림 | Major |
| 등급 부적절 | D·E등급 자료를 원출처 확인 없이 단정적 근거로 사용 | Major |
| 날조 위험 | 창업자 자료 없이 시험 결과·인터뷰 수·후기·계약·매출 실적을 서술 | Critical |

3. **다시 계산:** CAGR, 증감률, 합계, 비율 합 100%, TAM > SAM > SOM, 사업비(정부지원·자부담 비율, 비목 합계 = 총액), 원가율·마진, CAC·LTV. 계산식과 결과를 이슈에 적는다.
4. **일관성:** 같은 지표가 장마다 같은 값인지 본다. 특히 1장 요약 ↔ 2~5장, 1.2.1 목표 ↔ 4.3.1 일정 ↔ 4.3.2 사업비.
5. **범위 혼동:** 글로벌 수치를 국내 시장처럼 쓰거나, 스포츠웨어 전체 규모를 애슬레저 규모처럼 쓰는 경우를 찾는다.
6. **공고 규정:** 사업비 비율·한도·비목이 공고 팩트(`GOV-xx`)와 맞는지 확인한다. 공고 팩트가 없으면 "공고 미확인"으로 Major.
7. 웹 확인은 공식 출처만 쓰고 URL을 이슈에 적는다.

## 4. 검토 보고서 형식

`{WS}/03_{evaluator|fact-checker}_review_r{k}.md`

```markdown
# {평가위원 심사 | 팩트체크} — 라운드 r{k}

## 판정: PASS | REVISE
- Critical N · Major N · Minor N
- 판정 사유 2~3줄

## 1. 이전 라운드 이슈 처리 확인 (재검토 때만)
| ID | 이전 심각도 | 처리 상태(해결/부분/미해결) | 확인 내용 |

## 2. 이슈 목록 (심각도순)
| ID | 심각도 | 위치 | 원문 인용 | 문제 | 수정 방법 |

## 3-A. 소목차별 점수 (평가위원)
| 소목차 | 점수 | 한 줄 평 |
## 3-B. 대조표 요약 (팩트체커)
| 판정 | 개수 |  + 불일치·출처 없음·날조 위험 항목 전체 목록

## 4. 쪽수 점검 (평가위원) / 재계산 결과 (팩트체커)

## 5. 질문 (판단 근거가 부족해 리더·집필가에게 묻는 사항)
```

## 5. 판정 기준

| 역할 | PASS 조건 |
|------|----------|
| 평가위원 | Critical 0건, Major 2건 이하, 모든 소목차 3점 이상 |
| 팩트체커 | Critical 0건, "출처 없음"·"불일치"·"날조 위험" 0건 |

## 6. 재검토 규칙

- 이전 이슈의 처리 상태를 먼저 판정한다. 집필가의 변경 기록(`02_writer_changelog_r{k}.md`)을 참고하되 본문에서 직접 확인한다.
- 새 이슈는 **수정 과정에서 새로 생긴 문제**와 **이전 라운드에서 놓친 Critical**만 추가한다. 라운드마다 새 기준을 들이밀면 수정이 끝나지 않는다.
- 집필가가 "반영 안 함"으로 답한 이슈는 사유가 타당하면 종결하고, 타당하지 않으면 심각도를 유지한 채 사유를 적는다.

## 7. 하지 말 것

- 본문 파일을 고치지 않는다. 검토 파일만 쓴다.
- "더 설득력 있게", "보강 필요"처럼 수정 방법이 없는 지적을 쓰지 않는다.
- 상대 역할의 영역을 깊게 검토하지 않는다(평가위원의 수치 의심은 "팩트체커 확인 요청"으로 넘긴다).
