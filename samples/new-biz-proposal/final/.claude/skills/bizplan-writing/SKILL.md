# 정부지원사업 사업계획서 집필

평가위원은 짧은 시간에 수십 건을 읽는다. 각 소목차에서 "이 항목에서 확인하려는 것"에 바로 답하고, 그 답을 수치와 출처로 받치는 문서가 통과한다. 이 스킬은 그런 문서를 자료에서 끌어내는 절차다.

## 1. 기준 문서 — 원문이 우선이다

집필 전에 아래 두 파일을 **원문으로** 읽는다. 이 스킬은 실행 절차를 정리한 것이고, 규칙이 충돌하면 원문을 따른다.

- `custom-instruction/작가 페르소나.txt` — 관점(Evidence / Why us / So what), 문체, 작성 원칙, 금지사항
- `custom-instruction/사업계획서 목차.txt` — 대·중·소목차 번호와 제목, 쪽수 배분

소목차별 심사 포인트·필수 요소·추천 그림은 `references/section-guide.md`에 있다. 각 장을 쓰기 직전에 해당 부분을 읽는다.

## 2. 작업 순서

| 순서 | 산출물 | 왜 이 순서인가 |
|------|--------|---------------|
| ① 자료 읽기 | (메모) | 팩트 시트 `01_analyst-*_facts.md`, 데이터 인사이트 `01_data-analyst_insights.md`, 차트 자산 목록, 공고 팩트(`GOV-xx`)를 모두 읽는다 |
| ② 아이템 정의 | 수치 시트 0절 | 제품·타깃·차별점이 정해져야 모든 장이 같은 회사 이야기를 한다 |
| ③ 핵심 수치 시트 | `02_writer_numbers.md` | 같은 지표가 1장과 4장에서 다르면 바로 감점이다. 숫자를 먼저 한곳에 확정한다 |
| ④ 그림 계획 | `02_writer_figure_plan.md` | 그림이 들어갈 자리를 먼저 정해야 본문 분량을 쪽수 안에 맞출 수 있다 |
| ⑤ 본문 | `02_writer_draft_r0.md` | 2장 → 3장 → 4장 → 5장 → **1장(요약)은 마지막**에 쓴다. 요약은 나머지가 확정된 뒤에만 정확하다 |
| ⑥ 창업자 요청 목록 | `02_writer_founder_requests.md` | 초안이 비워 둔 칸을 창업자가 채울 수 있게 무엇을, 어떤 형식으로 줄지 적는다 |
| ⑦ 자기 점검 | (본문 수정) | 9절 점검표 |

### ② 아이템 정의

자료(비즈니스 모델 캔버스, 전략 보고서 등)가 정한 내용을 먼저 따르고, 정하지 않은 부분은 집필가가 결정해 `[가정]`으로 표시한다. 수치 시트 맨 앞에 다음을 적는다.

- 브랜드·제품명(가칭), 카테고리, 핵심 기능 3개(기능 → 측정 지표 → 시험 방법)
- 1차 타깃 고객과 구매 상황, 2차 타깃
- 기존 제품 대비 차별점(측정 가능한 축으로)
- 수익 구조(채널별), 가격대
- 결정 근거(팩트 ID)와 `[가정]`으로 둔 항목

### ③ 핵심 수치 시트 형식

```markdown
# 핵심 수치 시트 (실행 v{N}, 라운드 r{k})
## 0. 아이템 정의
## 1. 수치 목록
| 키 | 지표 | 값 | 단위·기준 | 근거(팩트 ID·계산식) | 태그 | 사용 소목차 |
|----|------|----|----------|---------------------|------|-----------|
| TAM | 국내 애슬레저 시장 규모 | … | 2024년, 소매 기준 | MKT-03 | [확인 필요: 원출처] | 2.2.1, 1.1 |
| REV-Y1 | 협약기간 매출 목표 | … | 협약 종료 시점 누적 | 객단가×구매자 수 (키 AOV, BUY-Y1) | [가정] | 1.2.1, 4.3.1 |
## 2. 충돌 메모 (자료 간 다른 값과 채택 사유)
```

- 계산으로 나온 수치는 계산식을 다른 키로 적는다. 팩트체커가 다시 계산할 수 있어야 한다.
- 본문에 쓰는 수치는 반드시 이 시트에 있어야 한다. 시트에 없는 수치를 본문에 바로 쓰지 않는다.

## 3. 태그 체계

| 태그 | 쓰는 경우 | 예 |
|------|----------|----|
| (출처: 기관·연도) | 출처가 확인된 수치·사실 | `(출처: 중소벤처기업부, 2026)` |
| `[확인 필요: 사유]` | 출처는 있으나 원출처 대조가 안 됨(D등급 등), 공고 세부가 미확인 | `[확인 필요: AI 리서치 재인용, 원출처 대조]` |
| `[가정]` | 집필가가 정한 값. 바로 뒤에 산정 논리를 붙인다 | `객단가 9.8만 원 [가정: 경쟁사 상의·하의 정가 중간값 기준]` |
| `[창업자 입력 필요: 무엇]` | 창업자만 가진 정보 | `[창업자 입력 필요: KOTITI 흡수속건 시험성적서 결과]` |
| `[그림 삽입: 내용]` | 그림 자산을 만들 수 없을 때만 | — |

- 팩트 ID(`MKT-03` 등)는 본문에 노출하지 않는다. 본문에는 기관·연도를, ID는 수치 시트에 둔다. 평가위원에게 내부 ID는 의미가 없기 때문이다.
- AI 리서치 보고서(D등급)를 인용할 때 그 보고서 이름을 출처로 내세우지 않는다. 원출처가 있으면 원출처를 쓰고 `[확인 필요: 원출처 대조]`를 단다. 원출처가 없으면 수치를 핵심 근거로 쓰지 말고 방향성 근거로만 쓰거나 `[확인 필요]`로 둔다.

## 4. 문체 규칙

페르소나 3절을 따른다. 자주 틀리는 부분만 예시로 정리한다.

- **소목차 첫 줄은 헤드라인 1문장**이다. 굵게 쓰고, 이어서 근거 bullet 3개 이내.
- 개조식, 명사형 종결(~함, ~임, ~예정). 한 문장 한 메시지, 50자 안팎.
- 형용사 대신 수치. 수치가 없으면 비교 대상이라도 밝힌다.

```markdown
#### 2.1.1 기존 스포츠웨어의 한계

**국내 운동 인구의 땀·체온 불편은 '소재'가 아니라 '부위별 설계' 부재에서 발생함**

- 고강도 운동 시 땀 배출량은 부위별로 최대 N배 차이 (출처: …) [확인 필요: 원출처 대조]
- 국내 주요 브랜드 레깅스 리뷰의 불만 1위는 '땀 자국·비침' (출처: …)
- 단일 원단 통짜 패턴 구조로 부위별 통기 차등 설계 불가

{{FIG:diagram-problem-tree}}

> [심사위원 예상 질문] 부위별 설계가 기존 브랜드의 메시 패널과 무엇이 다른가?
> [답변 포인트] 3.3.1의 바디맵 설계 근거와 통기도 비교 시험 계획으로 답변
```

- "최초·유일·독보적·획기적"은 근거가 있을 때만 쓴다. 근거가 없으면 쓰지 않는다.
- 경쟁사는 공개된 사실(가격대, 채널, 소재 표기)로만 비교한다. 평가 표현(품질이 낮다 등)을 쓰지 않는다.
- 블라인드 규정: 대표자·팀원 성명, 출신 학교, 특정 가능한 회사명 이력을 쓰지 않는다. "대표자", "팀원 A", "글로벌 스포츠 브랜드 소싱팀(7년)"처럼 쓴다. 공고 팩트(`GOV-xx`)에 해당 연도 규정이 있으면 그것을 따른다.

## 5. 쪽수 예산

목차의 쪽수 배분을 지킨다. A4 1쪽 ≈ 개조식 25~30줄. 그림 1개 ≈ 1/3쪽, 표는 행 수 + 2줄로 계산한다.

| 대목차 | 쪽수 | 본문 줄 수 예산(그림 공제 전) |
|--------|------|---------------------------|
| 1. 개요(요약) | 1쪽 | 25~30줄 |
| 2. 문제 인식 | 3쪽 | 75~90줄 |
| 3. 실현 가능성 | 3~4쪽 | 75~120줄 |
| 4. 성장 전략 | 3~4쪽 | 75~120줄 |
| 5. 팀 구성 | 2쪽 | 50~60줄 |

- 그림을 넣으면 그만큼 본문을 줄인다. 그림이 본문을 대신해야지 본문 위에 얹히면 안 된다.
- `[심사위원 예상 질문]` 메모는 작성용이며 제출본에서 빠지므로 쪽수에 넣지 않는다.

```
{{FIG:chart-market-growth}}
```

- 그림 ID 형식과 파일 규칙은 `.claude/skills/bizplan-orchestrator/references/visual-system.md`를 따른다.
- 데이터 차트는 데이터 분석가가 이미 만든 차트 ID(자산 목록)를 그대로 쓴다. 필요한 차트가 없으면 그림 계획에 `chart` 유형으로 요청을 남긴다.

### 그림 계획 형식 (`02_writer_figure_plan.md`)

```markdown
# 그림 계획 (실행 v{N})
## 시각 메모
- 브랜드(가칭)·키워드 3개·톤: 일러스트레이터가 스타일 기준을 정할 때 참고
## 그림 목록
| 그림 ID | 유형 | 위치 | 평가위원이 얻을 결론(1문장) | 내용 명세 | 근거(수치 키·팩트 ID) | 우선순위 |
|---------|------|------|---------------------------|----------|---------------------|---------|
| diagram-supply-chain | diagram | 3.2.2 | 원단~배송 전 과정에 검증 지점 4곳 | 원단 밀→재단·봉제(OEM)→QC→물류, 각 단계 리드타임 | LT-*, MOQ | 필수 |
| illust-product-kv | illustration | 1.1.1 | 제품 컨셉을 한눈에 | 바디맵 존별 기능 구분이 보이는 상·하의 착장 | 아이템 정의 | 필수 |
```

- 유형별 권장 수: 차트 2~4, 도해 5~7, 일러스트 3~5. 합계는 쪽수당 1개 안팎.
- 일러스트는 글이나 도해로 대신할 수 없는 경우에만 넣는다(제품 컨셉, 소재·구조 개념, 사용 장면). 도해와 같은 내용을 일러스트로 다시 그리지 않는다.
- 내용 명세에는 도해 디자이너·일러스트레이터가 본문을 다시 해석하지 않아도 되도록 노드·단계·요소를 구체적으로 적는다.

## 7. 소목차 블록 구성

각 소목차(`####`)는 아래 순서로 쓴다.

1. 헤드라인(굵게, 1문장)
2. 근거 bullet 3개 이내(수치 + 출처 또는 태그)
3. 필요하면 표(마크다운 표, 제목은 `**[표 2-1] 제목**`) 또는 `{{FIG:…}}`. 표 제목 줄과 표 사이에는 빈 줄을 둔다. 빈 줄이 없으면 변환기가 표를 문단으로 읽는다
4. `> [심사위원 예상 질문] …` 과 `> [답변 포인트] …` 메모

문서 구조:

```markdown
# {브랜드(가칭)} — {아이템 한 줄} 사업계획서 (초기창업패키지, 초안 v{N})

> 작성 기준일 · 문서 상태: 초안 · 태그 범례(표)

## 1. 창업아이템 개요 (요약)
### 1.1 창업아이템 소개
#### 1.1.1 제품명·카테고리 및 핵심 기능
…
```

목차의 번호·제목을 그대로 쓰고, 쪽수 표기(`[1쪽]`)는 제목에서 뺀다.

본문 파일에는 사업계획서 내용과 `[심사위원 예상 질문]` 메모만 둔다. 그림 목록·쪽수 추정·작업 메모는 변경 기록이나 수치 시트에 쓴다. 본문에 남은 작업 메모는 제출본에 섞여 나갈 수 있다(조립 스크립트는 제목에 "제출본 제외·작성 메모"가 있는 절만 제출용에서 지운다).

쪽수는 줄 수로 추정하되, 표 셀 줄바꿈과 그림 배치 때문에 실제보다 적게 나오는 경향이 있다. 실측은 리더가 시험 조립으로 하므로 자기 추정치는 참고용으로만 보고한다.

## 8. 수정 라운드

리더가 검토 파일(`03_evaluator_review_r{k}.md`, `03_fact-checker_review_r{k}.md`)을 넘기면:

1. 두 파일의 이슈를 모두 읽는다. Critical·Major는 반드시 처리하고, Minor는 쪽수·일관성을 해치지 않는 범위에서 처리한다.
2. 수정본은 새 파일 `02_writer_draft_r{k+1}.md`로 쓴다. 이전 라운드 파일은 고치지 않는다.
3. 수치가 바뀌면 수치 시트도 `02_writer_numbers_r{k+1}.md`로 새로 쓴다.
4. 변경 기록 `02_writer_changelog_r{k+1}.md`:

```markdown
| 이슈 ID | 심각도 | 처리 | 수정 위치 | 내용 또는 미반영 사유 |
|---------|--------|------|----------|---------------------|
## 영향받는 그림 ID (수치·구조가 바뀌어 다시 만들어야 하는 그림)
```

5. 두 검토가 서로 반대 방향을 요구하면(예: 평가위원은 수치 추가, 팩트체커는 근거 부족으로 삭제) 혼자 정하지 말고 리더에게 판단을 요청한다.
6. 수정하면서 새로운 근거 없는 수치를 만들지 않는다. 지적을 피하려고 수치를 지우기만 하지도 않는다. 근거를 보강하거나 `[창업자 입력 필요]`로 바꾼다.

## 9. 점검표 (제출 전 자기 점검)

- [ ] 목차의 모든 소목차가 번호·제목 그대로 있다
- [ ] 모든 소목차 첫 줄이 헤드라인이고 근거가 3개 이내다
